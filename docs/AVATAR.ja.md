# 標準の声・アバター

独立版`uagav`の「声・アバター」から開始します。本体の`uagw`・`uaga`と
Agent / Memory / Sandbox / 認証は変更していません。追加サーバー・ポートも不要です。

ZEN-LipSyncの標準アバターは**3体**、ZEN-TTSの標準音声は**4種類**です。
追加された「全力 カイ（kai）」は**音声モデルのみ**で、カイ専用アバターのモデルは
公式配布されていません。未公開のアバターを代用・生成したものとして扱いません。

| アバター（映像） | ID | 既定 |
| --- | --- | --- |
| 全力 マリン | marine | ○ |
| 全力 ハシロウ | hashiro | |
| 全力 キッカ | kikka | |

| ZEN-TTS音声 | ID | 既定 |
| --- | --- | --- |
| 全力 マリン | marine | ○ |
| 全力 ハシロウ | hashiro | |
| 全力 カイ（音声のみ） | kai | |
| 全力 キッカ | kikka | |

「アバター」と「音声」は別々に選べます。アバターを変更すると、最初はその
アバターと同名の音声に切り替わり、その後「カイ」を含む4音声から変更できます。
たとえば「ハシロウの映像＋カイの声」は可能ですが、カイ自身の映像ではありません。
音声のクローンやオリジナル素材の制作は行いません。AIによる映像である旨と、権利者指定のリンク付きクレジットを画面に
表示します。

## 初回セットアップ

SDK・モデル・素材は独自ライセンスで、アプリ内利用は許可されていますが改変・再配布は
禁止されています。リポジトリ・wheel・sdist・CI成果物には含めません。
個人の利用環境で公式配布元から取得して使います。素材を公開・共有サーバーで配信する
運用や、配布物への同梱を行う場合は事前に権利者への確認が必要です。

- [ZEN-LipSyncライセンス1.0](https://github.com/zenryokukikai/zen-lipsync/blob/v1.1.0/LICENSE.md): 3章のクレジット・改変/再配布禁止と4章の標準アバター利用条件。
- [ZEN-TTSライセンス1.0](https://github.com/zenryokukikai/zen-tts/blob/v1.1.0/LICENSE.md): 3章のクレジット・改変/再配布禁止。
- [SDKの第三者ライセンス](https://github.com/zenryokukikai/zen-lipsync/blob/v1.1.0/THIRD_PARTY_NOTICES.md)と[TTSの第三者ライセンス](https://github.com/zenryokukikai/zen-tts/blob/v1.1.0/THIRD_PARTY_NOTICES.md)も公式取得物に保持します。

GitとNode.js/npmを用意します。公式SDKの推奨はNode.js 26.12.1以上です。
`uag-web`のチェックアウト先で実行します（Windows / Linux / macOS共通）。

```sh
python scripts/setup_avatar.py
uagav
```

既定の取得先はホームディレクトリの`.uagav/zen`です。公式1.1.0のコミットを固定し、
ソースを改変せずビルドします。4種類の音声モデル（カイを含む）は公式CDNから取得し、公開SHA-256を
照合してから配置します。約230MB以上の素材に加え、ビルド用のディスク容量が必要です。
初回取得とSDKビルドにはネット接続が必要ですが、配置後のSDK・TTS・アバター処理は
同一オリジンから読み込み、ブラウザ内で実行します。LLM認証情報はサーバー側のままです。

場所を変える場合だけ、`UAGAV_ZEN_DIR`を指定します。スクリプトとWebの両方がこの
環境変数を使います。スクリプトはリポジトリ内への素材配置を拒否します。
取得先にある公式ソースを編集せず、更新は別PRでバージョン・ハッシュを検証します。
自動起動・自動ダウンロードはしません。

## 操作と制限

- 対応ブラウザのHTTPSまたはlocalhostで「アバターを開始」を押します。口パクには
  WebGPUが必要です。非対応環境でも既存のテキストチャットは利用できます。
- 返答の確定後、文ごとに音声を合成して口パク付きで読み上げます。コードブロックと画像URLは
  読み上げません。LLMのトークン到着中に読み上げる機能はまだありません。
- 「ZEN-TTS」のトグルスイッチで**CPU（既定）／WebGPU**を選択できます。切替は音声合成だけに適用され、
  リップシンクはどちらでもWebGPUを使います。アバター使用中に切り替えるとSDK・音声モデルを再初期化し、
  進行中の読み上げと連続聞き取りを停止します。必要なら「連続聞き取り開始」を押し直してください。
  WebGPU側の起動に失敗した場合はCPUに戻して再試行できます。自動フォールバック・速度に応じた自動切替はしません。
- 文ごとの小さな感情辞書で明確な happy / sad / apologetic の手がかりを判定し、ZEN-TTSへ渡します。
  曖昧な文は neutral とし、怒りは自動判定しません。追加のLLM呼び出しや感情分類モデルは使わず、
  否定の一部を考慮する簡易判定のため、皮肉や複雑な文脈は正しく判定できないことがあります。
- 1回の入力でツールを使うときは「ツールを利用します。少々お待ちください。」と1度読み上げます。
- 「音声停止」は読み上げを停止します。既存の停止操作、次の入力、ルーム/セッション変更、
  切断、human_askでも読み上げを停止します。履歴や再接続時には読み直しません。
- アバター変更・パネルを閉じる操作でSDKと音声のリソースを解放します。
  音声用AudioContextはモデル読み込み後に作成されるため、ブラウザーによっては
  モデル読み込み前のクリックだけでは再生が許可されません。アバター読み込み後の
  クリックやEnterキーで音声再生を再開します。再生できない場合は
  「再生を再開」を一度押し、改めてメッセージを送信してください。
  SDKの初期化・音声合成・再生の失敗原因はブラウザーのConsoleに記録します。
- 「連続聞き取り開始」は対応ブラウザの音声認識を使い、確定した認識結果の後は
  約0.8秒、未確定の途中結果では約1.1秒の無音で発話をチャットへ送ります。
  途中結果の間隔を短縮しないことで、言い淀み中の誤送信を抑えます。
  アシスタントの返答中と読み上げ中は認識を一時停止し、
  読み上げ後に再開します。ブラウザ提供元に音声が送信される場合があります。開始時に
  マイク許可が必要です。「聞き取り停止」でいつでも停止できます。
  ブラウザ非対応時は聞き取りボタンを出さず、テキスト入力を維持します。
- ツール実行やhuman_askの回答は既存UIと既存のサーバー権限判定を使います。
  これはAIアバターであり、全力機械の公式アプリや実在の人物との会話ではありません。

## アバター開始時間

アバターの映像モデルとZEN-TTS音声モデルの初期化は、互いの完了を待たずに
並列で開始します。両方が成功した場合のみ「アバターを開始」が完了します。
どちらかが失敗した場合は、もう一方の初期化終了を待って確保済みのリソースを
破棄します。選択したアバター・音声、公式SDK・モデルは変更しません。
CPU／WebGPUは画面上で明示的に切り替えられますが、自動最適化や速度改善の保証は行いません。

ブラウザのPerformance APIに`uagav:avatar-startup`（SDKの読み込み開始から、
アバターと音声の初期化完了までの所要時間）を記録します。
モデルの初回キャッシュ状態や端末性能で時間は変わるため、
並列化による短縮量を保証するものではありません。

## 対話遅延の計測

ブラウザのDevToolsのConsoleから、直近の音声対話の各区間をミリ秒で確認できます。
ユーザーの発話本文・会話ID・音声データは計測値に記録せず、外部へ送信しません。

```js
performance.getEntriesByType('measure')
  .filter((entry) => entry.name.startsWith('uagav:'))
  .map(({ name, duration }) => ({ name, ms: Math.round(duration) }))
```

- `uagav:mic-result-to-send`：最後の音声認識結果からWebSocket送信まで
  （無音判定とブラウザ音声認識の終了処理を含みます）
- `uagav:send-to-final`：送信からアシスタント応答確定まで
  （ネットワーク・サーバー待機・LLM推論・ツール実行を含み、LLM単体の時間ではありません）
- `uagav:final-to-first-tts-chunk`：回答確定から最初の音声PCMチャンク生成まで
  （実際にスピーカーから音が出る時刻ではありません）
ZEN-LipSync v1.1.0の`speechstart`は、SDKが音声ストリームの処理を始めた時点で
発火し、実際のPCM合成・スピーカー再生より**前**の場合があります。
そのため、実音声再生開始までの時間と誤解される`uagav:final-to-speech-start`計測は廃止しました。

各項目は最新の計測値だけを保持します。キャンセルされた対話や未完了の音声では
後続の計測を行いません。実機での対話速度・誤送信率の比較は別途必要です。

## ZEN-TTSのCPU／WebGPU実機比較

どちらの音声合成方式が速いかは、GPUの性能やブラウザーによって異なります。
`uagav`ではZEN-TTSの実行方式をCPU（既定）／WebGPUのトグルで選択できます。
この診断は**画面上の設定や対話状態を変更せず**、同じ公式音声モデルと固定のテスト文で両方式を比較します。

セットアップ後に`uagav`を起動し、デスクトップのWebGPU対応ブラウザーで実行します。
上記のPlaywright/Chromiumインストールを先に済ませてください。

```sh
node scripts/benchmark_tts_browser.mjs
# URLや音声を変える場合
node scripts/benchmark_tts_browser.mjs http://127.0.0.1:8000/ kai
```

Chromiumが一時的に起動しますが、アプリ本体を表示せず、同一オリジンの空の診断ページを使います。
会話履歴の取得や新しいルーム・セッションの作成は行いません。
CPUとWebGPUを**順番に**検証します。
それぞれ1回のウォームアップ後、3回の中央値をJSONで出力します。
実際の会話・マイク・LLMへのアクセスは行わず、固定テスト文を使います。
音声は再生せず、PCMを生成して計測します。

- `medianFirstChunkMs`：最初の音声チャンク生成までの待ち時間（小さいほど速い）
- `medianRtf`：音声の長さに対する合成所要時間の比（小さいほど速い）
- `loadMs`：モデルの初期化時間
- `error`：利用できない方式の理由（成功した方式の結果は保持）

ソフトウェアGPUの可能性があるため、`webgpu`の数値だけで物理GPU利用を
断定しません。実際にはZEN-LipSyncのWebGPU処理ともGPU資源を共有するため、
**TTS単独のベンチマーク結果だけでWebGPUの方が速いと決めつけないでください**。
実際の対話・口パクを動かしながらCPU／WebGPUを比較し、端末ごとに適した方を選んでください。

## 最終回答の逐次読み上げに必要な条件

現在のWebSocketの`assistant_stream_delta`は、**その時点で最終回答と確定した文章**
であることを保証しません。最終的にツール呼び出しが必要になることや、
`assistant_stream_replace`で出力が置き換わることがあるため、句点だけを見て
読み上げを始めると途中回答・推論・取り消された文章を話す危険があります。

将来的な逐次読み上げは、UAG本体から**最終回答として読み上げてよい**
ことを明示する信頼できる通知が提供されてから対応します。必要な条件は次の通りです。

- 通知元が現在のユーザー入力・ルーム・ターンと紐づき、再接続の履歴・snapshotではないこと
- 推論・ツール呼び出し・ツール結果の出力ではなく、読み上げ対象の最終回答であること
- 文章の差し替え、割り込み、キャンセル時に音声側も即座に破棄できること
- 一文が確定した単位で順番に読み上げ、二重読み上げをしないこと

現在は**未確定ストリームの自動読み上げを行いません**。既存の最終回答確定後の
読み上げを維持し、UAG側が保証していない段階で
`assistant_stream_delta`を最終回答だと推測しません。

## 検証

Nodeテストで確定文・置換・中断・履歴非再生・遅れて終了した合成のキャンセルを検証します。
Pythonテストで認証、素材パス制限、symlinkによる脱出拒否とJSのMIMEを検証します。
標準素材・声の実ブラウザ検証は別途実施し、PRに結果を記録します。CIには権利制限のある
素材を取得・アップロードしません。実マイク・実Provider会話・各実機での受入は別途必要です。

実ブラウザの再検証は、公式素材を配置して`uagav`を起動したうえで次を実行します。

```sh
npm install --prefix frontend --no-save --package-lock=false playwright@1.63.0
node frontend/node_modules/playwright/cli.js install chromium
node scripts/check_avatar_browser.mjs
```

WebSocketの返答だけをテスト側で送信し、実SDK・3体の実アバターと4種類の実声を使います。
音声バッファの再生開始・終了と切り替えを検証します。実LLM・マイクの検証ではありません。
このテストはWebGPUを使える検証端末で実行し、CIの必須テストには含めません。

### 再接続時のWebSocket通知

既存の`assistant_stream_start` / `assistant_stream_replace` / `assistant_stream_end`
を維持し、接続時に保持済みストリームを復元する通知だけ`"snapshot": true`を追加します。
既存チャット表示は従来どおり復元しますが、音声側はこのストリームを読み上げ対象にしません。
復元時点で処理中だったストリームも除外し、次の新しい返答から読み上げます。
通常のライブ通知と入力メッセージの形式は変えません。
